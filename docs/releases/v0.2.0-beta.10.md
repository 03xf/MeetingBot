# v0.2.0-beta.10 · 窗口唤醒与截图修复测试版（Windows）

针对隐藏一段时间后唤醒无响应、截图时浏览器报告“页面隐藏”的反馈，修正窗口唤醒与截图层的处理，并增加独立于界面的恢复入口。本版仍为测试预发布版。

**原来那次长期隐藏后无响应的根因尚未复现确认；Edge、Chrome 的真实鼠标 / 快捷键焦点和可见性验收，以及京东、腾讯、飞书、北森平台兼容性均未实测通过。不能将下述程序化回归当作这些平台已通过。**

## 下载

- 安装版：`MeetingBot-0.2.0-beta.10-win-x64.exe`
- 免安装版：`MeetingBot-0.2.0-beta.10-win-x64-portable.exe`
- 两个 EXE 均附 `.sha256` 校验文件；Windows 10 / 11 x64，未做代码签名。
- 离线焦点自检页：`MeetingBot-focus-check.html`。

先从托盘完全退出旧版，再安装或启动新版。设置中版本应为 `0.2.0-beta.10`。配置、知识库、历史记录和自定义提示词继续使用 `%APPDATA%\MeetingCopilot`。

## 本次修正

- **唤醒路径**：已处于浏览模式时，不再在每次隐藏 / 唤醒时重复写入原生焦点属性；显示后请求重绘透明窗口。继续使用不激活的显示路径。
- **截图层可见性**：Windows 截图层使用原生窗口透明度 `0.99`，保留不聚焦属性。CSS 透明背景本身不能代替原生透明度标志；该调整针对整屏截图层被判为不透明遮挡的路径，实际浏览器事件表现仍需在目标浏览器中测试。主窗口的透明度设置继续保留。
- **截图清理**：原始画面只编码一次。取图超过 10 秒、框选超过 90 秒会取消；选择层失去响应、渲染进程退出时也会取消。取消直接销毁临时选择窗口，过期回调不会重新打开它。未完成的原生取图请求不会被反复叠加。
- **恢复界面**：托盘新增 **恢复界面（停止录音和生成）**。使用时会结束录音、取消生成、关闭框选层，等旧渲染进程退出后重新加载界面，并恢复已保存的会话。未保存输入可能丢失；恢复后需要重新点击“开始”采集。
- **历史状态修复**：界面恢复或应用重启时，未完成的截图 / 自由提问会标为中断，保留已保存的部分文字；已归并的录音问题继续恢复到待确认区。
- **故障记录**：无响应、渲染进程 / GPU 退出、截图超时和恢复事件记录在本地 `window-faults.json`，最多 20 条，经过敏感信息过滤并纳入诊断报告。记录不包含录音、截图或对话正文。

## 建议复测

1. 用 Edge 或 Chrome 打开本版附带的自检页，开始记录；MeetingBot 使用浏览模式。
2. 先主动 Alt+Tab 校准失焦检测，再重新开始一轮，分别测试 Ctrl+B 隐藏 / 唤醒、点击回答、滚动、截图完成和各取消路径。
3. 使用模拟测评环境时，将“窗口失焦”“页面隐藏”“退出全屏”分开看；任意一项出现都应按对应原因继续定位，不能仅依据焦点没变判断通过。
4. 若再次卡住而托盘还能操作，选择 **恢复界面（停止录音和生成）**。恢复后打开诊断面板复制报告，或查看本地 `window-faults.json`。无需清空配置或知识库。

采集保护只控制画面采集排除，浏览模式控制窗口激活，二者都不代表真实平台兼容结果。飞书桌面客户端需要单独验证。

## 验证

- 类型检查、440 项 TypeScript 测试、8 项 Python 测试和构建；两条 ASR worker 本地模拟链路回归。
- 隔离配置、本地模拟模型和合成截图中，程序化验证反复隐藏 / 唤醒、隐藏后再显示、截图原生透明度与取消销毁、单次编码、恢复界面、取消生成、录音状态复位和保存会话恢复。
- 测试覆盖取图超时、未完成原生请求不叠加、过期回调、异常日志持久化与脱敏，以及各种回答中断后的历史恢复。
- 自定义提示词和透明度 UI / 实际模型请求回归；GitHub 发布流程验证安装包构建、打包后启动及 SHA256。
- 以上不等于真实浏览器输入验收；原始长期挂起现象与目标测评平台仍待实测。

技术依据：[Electron 41.1.1 的 SetFocusable 实现](https://github.com/electron/electron/blob/v41.1.1/shell/browser/native_window_views.cc)、[Chromium Windows 窗口遮挡判断](https://chromium.googlesource.com/chromium/src/+/master/ui/gfx/win/hwnd_util.cc)。
