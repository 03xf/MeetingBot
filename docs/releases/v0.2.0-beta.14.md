# v0.2.0-beta.14 · 按键选择录音区间（Windows）

回答快捷键改为两次切换：第一次标记起点，第二次标记终点，识别完成后只以两次按键之间的内容作为本轮问题。录音设备在区间之间保持运行。

## 下载与使用

- 安装版：`MeetingBot-0.2.0-beta.14-win-x64.exe`
- 免安装版：`MeetingBot-0.2.0-beta.14-win-x64-portable.exe`
- 两个 EXE 各附 SHA256，另附离线焦点自检页。
- 从托盘完全退出旧版后更新。知识库、提示词、会话、透明度和原有快捷键配置保留，无需迁移数据。
- 在编辑模式的设置里自行绑定 **“区间记录 / 结束并回答快捷键”**，例如单键 `Right`。沿用原字段和已有绑定；未设置时仍为空，不自动绑定。
- 点击“开始”，等 **“采集已就绪”**。初始化时显示“正在启动采集”。
- 第一次短按快捷键，显示 **“区间记录中”**；第二次短按，结束区间并等待识别、回答。结束时即使字幕还没出来，终点也按音频分界确定。
- 回答结束后可开始下一轮。在整理区间或生成回答时额外按键不会重复提交，请等待本轮处理结束。

## 区间与原有按钮

按键在音频处理线程标记分界，起点前、终点后的音频不拼入本轮问题；此次请求的最近转写上下文也只使用所选区间。知识库、提示词、资料和已完成回答历史继续按原设置工作。

左侧完整转写仍保留，也可能显示区间外内容；这是持续采集的原始记录。开始新区间会重新建立待确认集合，保留原始转写与历史回答。

未开启区间时，原“截到此刻并回答”按钮保留合并提交行为。记录中该按钮变为“结束区间并回答”，可以代替第二次按键；等待识别时仍可点击“取消提交”。停止采集、切换 / 新建 / 删除会话或清空转写会取消未提交区间，不自动回答。被取消区间的已识别转写仍可保留。

## 实现与验证

- 复用 AudioWorklet 的 PCM 尾帧冲刷和有序分界。worker 支持起点、终点连续排队；起点前的识别尚未结束时，也不会将终点移到之后的返回时间。
- 显式分界清除语音检测器闲置时的预留音频，避免起点前弱音进入下一段。同一设备不因每次按键重建。
- 类型检查、453 项 TypeScript 测试、8 项 Python 测试、构建及四条实际 worker / 本地模拟服务链路通过；流式与分段识别均验证三段不同 PCM 的隔离、短尾音、排队分界和延后停止。
- 隔离 Electron 使用实际 AudioWorklet、ASR worker 和本地模型服务，验证延迟字幕、连续两轮、空区间不提交、会话切换 / 停止取消、识别失败不提交，以及模型只收到区间内问题和最近转写。两轮选区只启动一次采集；隐藏操作没有显示或聚焦窗口。
- 浏览锁定、截图、恢复界面、自定义提示词、透明度和视觉请求回归通过。Windows 发布流程检查打包启动并核对 SHA256。

## 限制

- 首次采集仍需设备初始化。按键只标记已在采集的音频，不能补回初始化前的声音；结束后仍需等待识别和模型返回。
- 分界以音频线程收到标记的位置为准，不承诺与物理按键时刻逐采样完全一致。切在词中间可能影响识别；本版不额外删除区间内语气词。
- 本轮使用合成音频与程序化快捷键回调，没有真实录音、用户 Key 或计费接口；不能据此宣称原生键盘、鼠标验收通过。
- 独立浏览器与真实平台没有新增验收结论。此前 Edge 自动化正向校准无效、Chrome 自动化连接不可用；飞书、北森、京东、腾讯及飞书桌面客户端仍未实测。浏览模式和采集保护的适用范围保持不变。
